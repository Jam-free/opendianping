# OpenDianping（开放大众点评）产品提案

> 作者：Jam（华为小艺 PM）· 所属 side project：「美食肥猫」 · 版本 v0.1 · 2026-10-18

## 一句话定位
**把散落在视频/帖子里的美食和锁在大众点评收藏夹里的店铺数据"放出来"，让用户自己的 AI 能用。**

## 痛点
| # | 痛点 | 现状 |
|---|---|---|
| 1 | 视频、帖子里看到的好吃的，要手动搜索 → 找店 → 到点评里保存 | 长视频里提到 10 家店，逐个暂停、搜索、收藏，流失严重 |
| 2 | 收藏进点评的只是店名清单，位置、shopId、菜品等数据拿不出来 | 点评未开放数据，用户自己的收藏无法给地图/AI/其他工具用 |

## 用户旅程（以旅行为例）
- **行前 · 做攻略**：Jam 计划周末去长沙，刷了 3 个 20 分钟的探店视频和几篇小红书帖。以前要边看边记；现在把链接丢给「美食大爆炸」，1 分钟后拿到 12 家店 + 招牌菜清单，确认后一键进点评收藏。
- **途中 · 随机应变**：到了五一广场，没按攻略走，路边一家粉店排长队、吃完惊艳。打开「一键收藏当前店」，发送当下定位，系统匹配附近点评店铺，点一下确认即收藏。
- **随时 · 问 AI**：晚上 Jam 问小艺："明天中午在橘子洲附近，按我收藏的店排一条顺路路线，人均 80 以内，告诉我每家必点什么、要不要排队。"AI 读取 Jam 的点评收藏数据直接回答，必要时帮忙预约。

## 三大功能
### 功能 1「美食大爆炸」（行前）
| 项 | 内容 |
|---|---|
| 用户动作 | 粘贴视频/帖子链接 → 查看提取结果 → 勾选 → 一键收藏 |
| 系统流程 | 视频/图文解析 → 抽取 店名/菜品/城市/置信度 → 匹配点评 shopId → 校验 → 写入收藏 |
| 数据 | 店名、菜品、城市、置信度、shopId、评分、人均 |
| 可行性 | ✅ 解析：美食肥猫 parse bench 原型已有（视频→店/菜/城市/置信度）<br>⚠️ 匹配：点评搜索有验证墙，shopId 难拿；拿到 id 后用 m.dianping.com/shop/{id} 校验已跑通<br>❌ 写入点评收藏：**未验证可经公开接口实现** |

### 功能 2「一键收藏当前店」（途中）
| 项 | 内容 |
|---|---|
| 用户动作 | 一键发送当前定位（可选拍照/店名）→ 选中候选店 → 收藏 |
| 系统流程 | 定位 → 附近店铺候选 → 用户确认 → 写入收藏 |
| 数据 | 经纬度、候选店名、shopId |
| 可行性 | ⚠️ 附近店铺检索：待验证（同样受搜索验证墙影响）<br>❌ 写入点评收藏：同功能 1，未验证 |

**"加入点评收藏"的解法（功能 1/2 共用，待定）：**
| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 深链一键保存 | 生成点评店铺 deep link，用户点开在 App 内手动点"收藏" | 合规、无需登录凭证 | 每家点一次，非真"一键" |
| B. 自有收藏库 | 先存进 OpenDianping 自己的库，后续再同步 | 体验最顺，数据完全可用 | 不在点评里；同步方式未定 |
| C. 登录态自动化 | 用户在浏览器/App 自动化中登录后代为操作 | 真一键 | 账号风险、协议风险最高，不建议 MVP |

建议：MVP 用 **B + A**（自有库为主，提供深链跳转点评收藏）。

### 功能 3「开放能力」（随时）
| 项 | 内容 |
|---|---|
| 用户动作 | 在点评里把收藏专辑"分享" → 把链接贴给 OpenDianping → 授权给自己的 AI |
| 系统流程 | 解析专辑 albumid → 调用专辑分享页所用公开接口分页拉取 → 补充店铺页推荐菜 → 结构化存储 → 以 **MCP Server / API** 暴露 |
| 能力 | 导出（CSV/JSON）、地图展示、AI 问答：顺路探店路线、某店推荐菜与注意事项、（远期）预约 |
| 可行性 | ✅ 专辑拉取已跑通（无需登录/cookie/验证码）<br>✅ 店铺页推荐菜已跑通<br>⚠️ 坐标系推测为 GCJ-02，未验证<br>❌ 预约、完整地址/电话/营业时间：需登录，暂不可得 |

点评自身没有开放此能力，这是**增量价值**：任何 AI（含小艺、Claude 等）都能读用户自己导入的点评数据。

## 数据字段表（已验证来源）
| 来源 | 字段 | 登录 |
|---|---|---|
| `GET mapi.dianping.com/mapi/collect/getfavoralbumdetail.bin?albumid=&type=&nextstart=`（带 `favorVersion=3.0`） | 店名、shopId、uuid、城市/品类/商圈、评价数、5 分制评分、星级、人均、推荐语、标签、封面图、分享链接 | 否 |
| 同接口（不带 favorVersion） | 真实经纬度（推测 GCJ-02，未验证） | 否 |
| 同接口分页 | `type=1&nextstart=…` | 否 |
| 专辑元信息 | 标题、店铺数、创建/更新时间、作者 | 否 |
| `m.dianping.com/shop/{shopId}` | 商圈、推荐菜列表（地址/电话打码，坐标为 0） | 否 |
| — | 完整地址、电话、准确营业时间、作者对单店的备注、按 userId 列出用户全部专辑（需 App 签名，未伪造） | **需要，暂不可得** |

## MVP 范围与优先级
| 优先级 | 范围 | 理由 |
|---|---|---|
| **P0** | 功能 3 最小闭环：**贴专辑链接 → 导出 + 地图 + AI 可问（MCP）** | 链路已全部跑通，最快验证"数据放出来有没有人要" |
| P1 | 功能 1：链接 → 店/菜提取 → 存自有库 + 点评深链 | 解析原型已有，卡点在 shopId 匹配 |
| P2 | 功能 2：定位 → 附近候选 → 收藏 | 依赖附近检索方案，频次与场景待验证 |
| 不做 | 登录态自动化写入、预约 | 风险高、未验证 |

## 风险
| 风险 | 说明 | 应对 |
|---|---|---|
| 非官方接口可变 | 接口/参数随时可能改或加校验 | 多源兜底、监控告警、本地缓存已导入数据 |
| 平台协议 | 抓取与再分发可能违反点评用户协议 | 仅处理用户本人主动提交的数据，不做公开分发，不做批量爬取 |
| 只读、依赖主动分享 | 只能读用户分享出来的专辑，无法自动列出全部收藏 | 引导流程做顺："分享→复制→粘贴"三步 |
| 低频 | 旅行是低频场景 | 叠加本地日常场景（周末吃什么）、AI 问答提高复用 |
| 匹配准确率 | 视频店名模糊、同名店多 | 置信度展示 + 用户确认 |
